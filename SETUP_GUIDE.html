2. Local tools Required

  • Node.js 18 or newer (Express 5 and Vite 5 need it). Download the LTS build from nodejs.org, then check with node -v.
  • Git, from git-scm.com, to clone and push the repo.

Then install dependencies from the project root:

git clone https://github.com/muheebnuaku/Genericbot.git
cd Genericbot
npm install
cd client && npm install && cd ..
cp .env.example .env      # Windows PowerShell: Copy-Item .env.example .env
Never commit .env. It is already in .gitignore. Only .env.example (placeholders) belongs in git.

3. Meta / WhatsApp Cloud API Required

The server refuses to start (Missing required environment variable) unless these three are set: VERIFY_TOKEN, WHATSAPP_TOKEN, PHONE_NUMBER_ID.

3.1 Create the business & app

  1. Sign in at business.facebook.com and create a Business Portfolio if you don't have one.
  2. Go to developers.facebook.com/apps → Create app → use case “Connect with customers through WhatsApp” (type Business) → link it to your Business Portfolio.
  3. In the app, open WhatsApp → API Setup. Meta gives you a free test number straight away; you can use it before you register a real one.
  4. Under “To”, add and verify your own phone number as a test recipient (the test number can only message up to 5 verified numbers).

3.2 PHONE_NUMBER_ID

On the same API Setup page, copy Phone number ID. It's a long number, not the phone number itself.

3.3 WHATSAPP_TOKEN (make it permanent)

The token shown on API Setup expires after 24 hours. For anything beyond a quick test, create a permanent one:

  1. Business Settings → Users → System users → Add. Create an Admin system user.
  2. Assign assets: add your app (full control) and your WhatsApp account.
  3. Generate new token: pick your app, expiry Never, and tick whatsapp_business_messaging and whatsapp_business_management.
  4. Copy the token into WHATSAPP_TOKEN. It is shown only once.

3.4 VERIFY_TOKEN

You make this up. It's any random string, used only so Meta can prove the webhook belongs to you. Generate one with:

node -e "console.log(require('crypto').randomBytes(24).toString('hex'))"

Use the exact same value in .env and in Meta's webhook settings (step 4).

3.5 Going live (do this early, it takes days)

  • Business Verification: Business Settings → Security Center → Start verification (needs business documents).
  • Register a real number: WhatsApp Manager → Phone numbers → Add. The number must not be in use on the normal WhatsApp app.
  • Display name review: submitted in WhatsApp Manager; approval is required before customers see your name.
  • Payment method: add one in WhatsApp Manager for business-initiated conversations (broadcasts).
  • Switch the app from Development to Live mode (needs a privacy-policy URL).

4. Public URL & webhook Needed to work

Meta must reach your server over public HTTPS. localhost won't work.

Testing on your PC: ngrok

  1. Sign up at ngrok.com, install it, and run ngrok config add-authtoken <your-token>.
  2. Start the bot (npm start), then in a second terminal run ngrok http 3000.
  3. Copy the https://….ngrok-free.app URL.

Connect it in Meta

  1. App dashboard → WhatsApp → Configuration → Webhook → Edit.
  2. Callback URL: https://YOUR-URL/webhook
  3. Verify token: the same value as VERIFY_TOKEN. Click Verify and save. The server logs [Webhook] Verified successfully.
  4. Under Webhook fields, Subscribe to messages.

Set BASE_URL to the same public URL (no trailing slash). The bot uses it for media links and a keep-alive ping.

5. MongoDB Atlas Needed to work

Without MONGODB_URI the bot runs in memory and forgets every conversation, member and broadcast on restart.

  1. Create a free account at mongodb.com/atlas → Build a cluster → pick the free M0 tier.
  2. Database Access → Add user: username + password (avoid symbols like @ : / ?, or URL-encode them).
  3. Network Access → Add IP: your IP for local testing; 0.0.0.0/0 for cloud hosts like Render whose IPs change.
  4. Connect → Drivers, then copy the connection string and put your password in it: 
    MONGODB_URI=mongodb+srv://botuser:YOURPASSWORD@cluster0.xxxxx.mongodb.net
MONGODB_DB_NAME=whatsapp-bot

On start, the log should say Database: MongoDB Atlas ✅.

6. AI provider Needed to work

This produces the bot's replies. Without it, every message gets “I'm having a brief technical issue right now…”.

The code in src/services/aiService.js → callAiProvider() expects an HTTP endpoint with this contract:

RequestPOST {AI_API_BASE_URL}/v1/chat
Header Authorization: Bearer {AI_API_KEY} (sent only if the key is set)
Body{ message, system, history:[{role,content}], temperature, max_tokens, response_language, web_search }
Response{ "reply": "...", "sources": [] } or { "data": { "message": "...", "sources": [] } }

Choose one option

A. You already have an API with that shape: set AI_API_BASE_URL and AI_API_KEY and you're done.
B. Use a mainstream LLM (Claude, OpenAI, Gemini…): their APIs use a different shape, so edit callAiProvider() to call them directly. For example, with the Anthropic API:
  1. Get a key at console.anthropic.com → API Keys (billing required).
  2. Set AI_API_BASE_URL=https://api.anthropic.com and AI_API_KEY=sk-ant-….
  3. In callAiProvider(), POST to ${ai.baseUrl}/v1/messages with headers x-api-key, anthropic-version: 2023-06-01, and body { model, max_tokens, system, messages: [...historyPayload, {role:"user", content: message}] }.
  4. Read the reply from response.data.content[0].text and use sources = [].

Also rewrite rules 1–10 in buildSystemPrompt() for your business. They are currently written for a fact-checking bot. Keep rules 11–12; they fix WhatsApp formatting.

7. Knowledge base / Claims API Optional

This lets the bot cite your own published records (FAQ, help articles, catalog, fact-checks). Without it the bot still chats, but only from the AI's general knowledge.

src/services/claimsApi.js expects:

AuthAuthorization: Bearer {CLAIMS_API_KEY}
SearchGET {CLAIMS_API_BASE_URL}/claims?q=…&per_page=3
SingleGET {CLAIMS_API_BASE_URL}/claims/{id}
Record fieldsid, title, content, source, topics, regions, language, url, published_at, updated_at, cover_image_url, verdict{verdict, summary, research, reference_link, checked_at, fact_checker}

If your data source looks different, either build a small API with this shape or edit normalizeClaim() and the request paths to match yours. Leave both variables blank to skip this.

8. Admin dashboard login Needed to work

The dashboard at /app uses these credentials. The defaults (admin / change-me) are public, so change them before deploying.

ADMIN_USERNAME=admin
ADMIN_PASSWORD=a-long-unique-password
JWT_SECRET=paste-output-of-the-random-command-from-3.4

9. Company details Optional

These go into the AI's system prompt and the messages users see. The defaults say “Your Company”, so fill them in before real users see the bot.

COMPANY_NAME, COMPANY_INDUSTRY, COMPANY_DESCRIPTION (the most important one: describe what the assistant is for), COMPANY_WEBSITE, COMPANY_PHONE, COMPANY_EMAIL, COMPANY_ADDRESS, COMPANY_TONE, COMPANY_BUSINESS_HOURS, ESCALATION_WHATSAPP (the human who receives “talk to a person” handoffs).

12. Deploy to Render

Use an always-on Node host (Render, Railway, a VPS). Serverless platforms don't fit, because the bot processes messages in the background after replying to Meta.

  1. render.com → New → Web Service → connect the GitHub repo muheebnuaku/Genericbot.
  2. Build command: npm install && npm run build
  3. Start command: npm start
  4. Environment: add every variable from your .env. Type secrets in by hand; pasted values can pick up a hidden trailing space or newline that breaks login.
  5. After deploying, point Meta's webhook at https://your-service.onrender.com/webhook (§4).

The free tier sleeps when idle. The built-in keep-alive pings /api/health every 14 minutes, which also counts against your free hours.

No [Message] logs at allWebhook not subscribed to messages, or ngrok URL changed (free ngrok URLs change on restart).
